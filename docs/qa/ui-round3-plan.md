# UI 독립 검수 3회차 계획

작성일은 2026-10-18 KST다. 검수자는 구현자와 다른 에이전트 `/root/ui_round3`이며, 승인 근거는 `docs/design/0.1.0/design.md`, `test-plan.json`과 사용자가 전달한 구현 계획이다. 개인 magicsih 저장소이므로 Seorilabs 조직 계약과 원격 검증기를 적용하지 않는다.

## 실행 시점과 대상

- 최종 후보 SHA와 Release 앱 경로를 구현자에게 전달받은 뒤 기록한다. 그전에는 앱 실행, 테스트, 빌드와 화면 조작을 하지 않는다.
- 공유 화면과 Xcode 테스트의 충돌을 피하도록 2회차 검수 종료와 구현자의 실행 허용 메시지를 기다린다.
- 대상은 Apple Silicon용 Leaflit 0.1.0 로컬 Release 후보와 같은 소스의 macOS 개발 테스트다. 최소 지원 macOS 14와 실제 검수 OS를 구분하며 이전 OS 실행을 추정하지 않는다.
- 시스템 상태는 읽기로 확인한다. 사용자 문서, Finder 기본 연결과 PATH를 변경하지 않는다. 모바일 기기 접근과 외부 배포는 하지 않는다.

## 격리 데이터와 증거

기존 `Fixtures`는 읽기만 하고 시작 전후 SHA-256을 비교한다. 갱신, 삭제, 오류 복구용 문서는 `build/qa-round3` 아래에 복사하거나 새로 만든다. 삭제와 덮어쓰기는 검수자가 만든 이 데이터에만 한다.

실제 앱 화면과 접근성 트리를 `cua_repl`에서 읽어 동작을 판단한다. 화면을 보지 않고 DOM이나 소스만 읽은 검증은 UI 통과로 기록하지 않는다. 전체 자동 검증 로그, Release 빌드 로그, 실행 환경, 후보 SHA와 결과를 `docs/qa/ui-round3.md`에 연결한다. 성공, 실패, 도구 제한과 미실행을 따로 적는다.

## 실제 앱 검수 순서

| 범위 | 행동 | 기대 결과 |
| --- | --- | --- |
| 첫 화면과 파일 열기 | 빈 상태, Open 메뉴와 실행 도구로 공백 및 한글 경로의 문서를 연다. 같은 파일을 다시 열고 별도 파일도 연다. | 읽기 화면으로 이동하고 중복 파일은 기존 창을 활성화하며 별도 파일은 별도 창을 사용한다. |
| 이동과 메뉴 | 상대 링크와 중복 제목 앵커를 누르고 도구 막대, View 메뉴와 지원되는 키 입력으로 돌아온다. 검색과 복사를 실행한다. | 현재 문서와 창이 의도한 대로 바뀌며 이전 읽기 위치가 복원된다. 검색 결과 이동과 복사가 동작한다. |
| 일반 저장과 교체 저장 | 긴 문서 중간을 읽은 상태에서 일반 저장, 원자적 파일 교체 저장과 빠른 연속 저장을 한다. | 마지막 내용이 표시되고 읽던 블록의 화면 위치가 유지된다. |
| 동일 내용과 주변 파일 변경 | 같은 내용을 다시 저장하고 같은 디렉터리에 관계없는 파일을 만든 뒤 문서 링크를 누른다. | 화면이 그대로 유지되고 링크 이동과 Back이 계속 동작한다. |
| 삭제와 복구 | 검수용 파일을 삭제하고 이전 본문과 실패 상태, Retry와 Open을 확인한 뒤 파일을 복구한다. | 원문 삭제가 앱 종료나 빈 화면으로 이어지지 않고 이전 화면임을 알린다. 복구 후 최신 문서를 다시 읽을 수 있다. |
| 읽기 실패 | 잘못된 UTF-8을 검수용 문서에 저장한 뒤 복구한다. | 짧은 오류와 복구 행동을 제공하며 복구 후 정상 표시한다. |
| 보안과 오류 | 악성 HTML, 위험한 URL, 원격 이미지, 잘못된 수식과 Mermaid를 표시한다. | HTML과 오류 원문을 읽을 수 있고 스크립트, 원격 자원과 위험한 URL이 실행되지 않는다. 수식 오류의 테두리가 한 영역으로 이어진다. |
| 로컬 이미지 | 허용된 PNG와 JPEG, 누락 이미지와 형식이 잘못된 이미지를 연다. | 허용된 이미지는 보이고 나머지는 대체 텍스트가 보인다. |
| 읽기 환경 | 작은 창, 200% 확대, 라이트와 다크 모드, 키보드와 가능한 VoiceOver 실제 탐색을 확인한다. | 본문을 읽을 수 있고 코드와 표는 가로 이동할 수 있다. 다이어그램의 접근성 이름에 실제 노드 글자나 설명이 있다. 보조기술 결과와 도구 제한을 구분한다. |

1회차와 2회차의 실제 결과를 읽어 해결된 사항과 남은 사항을 구분한다. 이 회차에서 재실행하지 않은 항목을 새 후보의 통과로 바꾸지 않는다. 네트워크 차단은 CSP와 WebKit 요청 차단을 실제 통합 테스트에서 확인하고, OS 전체 네트워크를 끈 실행 여부는 별도로 기록한다.

## 전체 자동 검증과 최종 빌드

구현자가 최종 후보와 독점 실행 시점을 전달한 뒤 다음 명령을 독립 실행한다.

```sh
./scripts/verify.sh Release
./scripts/build.sh Release
```

`verify.sh`는 잠금 파일에 따른 웹 의존성 설치, 웹 문법 테스트, 배포 의존성 취약점 조회, 웹 자산 빌드, Foundation 모듈 테스트와 실제 WKWebView 통합 테스트 전체를 실행한다. 통합 테스트에는 Markdown과 Unicode, 수식과 Mermaid, 잘못된 문법과 악성 내용, 상대 이동과 복귀, 파일 교체와 연속 저장, 오래된 렌더링 취소, 로컬 이미지와 스크롤, 1MiB와 5MiB 문서, 원문 불변, 100KiB 20회 문서 전환, 외관과 확대, 외부 fetch 차단, 갱신 지연 측정이 포함된다.

최종 Release 빌드 뒤 소스와 생성 자산 diff를 읽고 시작 후보와 달라졌는지 보고한다. 빌드 성공, 자동 검증 성공과 실제 UI 검수 성공은 따로 기록한다. 앱과 도구의 서명, 공증, 공개 배포는 이 검수 대상이 아니다.

## 실행 전 소스 검토

2026-10-18 검토에서 `reload(preserve:)`가 동일 내용 읽기와 읽기 실패에도 먼저 갱신 번호를 올리는 점을 발견해 구현자에게 전달했다. 웹 화면의 번호가 이전 상태로 남으면 링크 메시지가 거부될 수 있으므로 위의 동일 내용 저장, 주변 파일 변경과 오류 상태 검수에 포함한다. 현재는 소스 관찰이며 실행 실패로 확정하지 않는다. 소스는 수정하지 않았다.

렌더링 완료 후 스크롤 복원이 다시 실행되는 구조이므로 비동기 다이어그램 처리 중 사용자가 이동한 위치가 덮이는지도 관찰한다. 구현자는 이 두 항목을 고쳤다고 전달했으며 최종 후보에서 동작으로 확인한다. 접근성은 버튼 이름과 문서 트리뿐 아니라 실제 입력과 이동 결과로 판단한다. 2회차에서 Cmd+F5로 VoiceOver가 활성화되지 않았으므로 필요하면 시스템 VoiceOver 앱 또는 Utility를 화면 도구로 열어 활성화와 실제 탐색을 시도하고 기존 상태로 복원한다.
