## Homebrew publication and isolated installation

The live registered `magicsih/tap/leaflit` recipe contains version 0.2.0 and the exact final ZIP checksum. Ruby syntax and `brew style --cask magicsih/tap/leaflit` passed. The clone-based initial style attempt was rejected because it was outside a registered tap; the actual registered-tap check passed afterward.

To preserve the user's existing application and command, installation used Homebrew's actual Ruby installer and the unchanged published recipe with a process-local isolated Caskroom and app directory. Global binary linking was disabled. This exercised the real public download, checksum validation, archive extraction, app installation and quarantine, without replacing the active `/Applications/Leaflit.app` or its launcher. The isolated installed executable, icon and bundled launcher matched the verified artifact. Strict signature, stapled ticket and Gatekeeper passed, and the actual quarantine attribute was present.

The first harness attempt stopped before installation because Homebrew cleared its task-specific environment variable. The harness then resolved its owned directory from its own file location. That failed setup attempt remains separate in local evidence.

The quarantined installed app initially waited before entering app code, and native automation timed out. An exact CoreServicesUIAgent observation then revealed the normal macOS first-open confirmation, attributed to the Homebrew download. The independent executor chose Open through native UI. The same owned app process then rendered plan.md with Mermaid and math, and its own `Contents/Resources/leaflit` opened the space-containing Release Preview.md in that exact app. The initial timeout, process sample, confirmation AX/screenshot and completed execution remain separately recorded. No quarantine removal or security-setting change occurred: the OS changed the quarantine flag from `0381` to `03c1` during normal approval, and the attribute remained. Post-execution strict signature and Gatekeeper passed, with assessments enabled.

A normal global CLI upgrade and global 0.2.0 command symlink were not executed. The existing global Homebrew receipt remains 0.1.0, and its command still points to the preserved 0.1.0 app. Users can upgrade through the published cask; this report distinguishes that availability from the isolated installation actually tested.

The first online audit failed on GitHub authentication. After verifying the existing active GitHub CLI account, the audit received that session only in its process environment, without credential changes or exposed values. It then reported exactly one policy failure: **`v0.2.0 is a GitHub pre-release.`** The full online audit is therefore not passed. Personal tap availability is separate from [official Homebrew cask readiness](https://github.com/magicsih/leaflit/issues/6).
